# floppy.io｜システム構成

### 🛠️ アーキテクチャ概要

floppy.io は、1 投稿をフロッピーディスク 1 枚分の **1,474,560 バイト**に収めるレトロ SNS です。ブラウザで本文を書き、AA を挿入し、ドット絵を描けます。投稿フォームに使用バイト数を表示し、FastAPI が保存する前に容量を検証します。

| レイヤー | 技術スタック | 選定理由・特徴 |
| :--- | :--- | :--- |
| **フロントエンド** | Nuxt 4・Vue 3（Composition API） | 投稿フォーム、AA パレット、タイムラインなどをコンポーネント化。SPA として静的ビルドを配信。 |
| **ドット絵・AA** | HTML Canvas・localStorage | 16 色のドット絵を描いて投稿。自作 AA、お気に入り、使用履歴はブラウザ内に保存し、挿入した AA は投稿本文に含める。 |
| **バックエンド API** | Python・FastAPI・Uvicorn | 認証、投稿、フォロー、コミュニティ「ディスク」への参加を扱う。投稿の保存前に本文・ドット絵・添付の合計容量を検証。 |
| **データベース・添付** | MySQL・PyMySQL・ファイルシステム | ユーザー、投稿、ドット絵、添付の情報をデータベースで管理。アップロードされたファイルはディスクに保存。 |
| **PWA** | Web App Manifest・Service Worker | 対応ブラウザでインストールできる。オフライン起動時は再読み込みの案内を表示。 |
| **Bot** | Python・Ollama・マルコフ連鎖 | キャラクターごとに文章を生成して投稿や返信に使用。タイムラインでは人間の投稿と Bot の投稿を切り替えて読める。 |
| **公開・共有** | Cloudflare Tunnel・Starlette ゲートウェイ・Open Graph | 公開ゲートウェイで静的ファイルと API を振り分ける。SNS クローラーには投稿ごとの共有メタデータを返す。 |

### 🔧 実装のポイント

1. **バイト数を見ながら 1 投稿を仕上げる**  
   本文の UTF-8 バイト数、キャンバスの容量、画像・ファイルのサイズを足し、投稿フォームに表示します。API でも受け取ったデータから改めて計算します。YouTube は本文の URL から埋め込みに必要な情報を取得し、入力した URL の文字列を本文の容量に含めます。
2. **ドット絵を 1 マス 1 文字で保存する**  
   16 色のパレット番号を 16 進数の 1 文字で表現します。16×16、32×24、32×32 のキャンバスを用意し、それぞれ 256、768、1,024 バイトを投稿の容量に数えます。
3. **AA を名前やキーワードから見つける**  
   プリセットに名前と検索用キーワードを持たせ、カテゴリを横断して検索できます。挿入時に、1 行の顔文字は必要に応じて空白を、複数行の AA は改行を補い、本文のカーソル位置に入れます。
4. **同じ投稿 URL を閲覧と共有に使う**  
   通常のアクセスには Nuxt の画面を返し、SNS クローラーには FastAPI が生成した Open Graph メタデータ付きの HTML を返します。ドット絵の投稿では、描画内容を 1,200×630 ピクセルの共有カードに使えます。
